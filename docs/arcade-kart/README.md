# Arcade kart foundation — review package

**Implementation update:** the user selected a browser-native game for the Unlike Hero hub. The active implementation is now in [`games/crownfall-kart`](../../games/crownfall-kart/README.md). The Unity source below is retained as the earlier architecture reference and is not needed to run the browser game.

This is Unity 6 C# source, targeting the Unity 6 Rigidbody API (`linearVelocity`, `linearDamping`). Copy `Unity/Assets/ArcadeKart` into a Unity project. It is a foundation for review, not a playable build or a complete Unity project: scenes, prefabs, artwork, checkpoint navigation, game modes, networking and hub integration are not supplied yet. There is no Unity editor installed in this workspace, so engine compilation and driving feel remain to be verified in Unity.

The existing Unlike Hero hub serves browser games. A Unity version would need a WebGL build, an HTML launcher, a hub SDK bridge and an authoritative multiplayer design. This package does not register an unfinished game in the hub. Confirm the Unity/WebGL direction during review before those integration costs are incurred.

## Architecture and ownership

```text
ArcadeKart/
  Runtime/
    Driving/
      KartTuning.cs              ScriptableObject: weight class and handling parameters
      KartController.cs          Rigidbody sphere, ground probe, drive, drift, boosts, hit state
      KeyboardKartInput.cs       W/S, A/D, Shift brake, Space hop/drift, E use item
    Race/
      RaceParticipant.cs         Stable racer identity; RaceProgress value and abstract source
    Items/
      ItemTable.cs               Weighted loot, front/middle/last bands, safe fallback
      ItemInventory.cs           One held item, coin count, collection/use events
      ItemManager.cs             Loot/execution/target selection; abstract autopilot port
      ItemBox.cs                 Shared box cooldown; inventory-full rejection
      KartProjectile.cs          Swept collision, homing, current-leader-only hunter
      DroppedTrap.cs             Armed stationary trap, owner exclusion, lifetime
    AI/
      AIManager.cs               Smoothed distance-based speed/acceleration modifiers
    Track/
      SurfaceVolume.cs           Composable mud speed restrictions, boost override
      MovingHazard.cs            Kinematic moving trigger, spin and momentum loss
      TrackTheme.cs             Swappable theme ScriptableObject
      TrackThemeManager.cs       Visual environment, skybox, ambient light and fog
  Editor/
    CreateKartDefaults.cs        Menu creates Light/Medium/Heavy/Items/ShatteredCrown assets
    ValidateKartFoundation.cs   Executable editor checks without a test-framework dependency
  Data/                         Generated by the menu; designer-owned assets

Proposed phase-two additions (not implemented):
  Runtime/Track/
    TrackDefinition.cs          Centreline, ordered checkpoint gates, lap length, spawn poses

    WaypointCircuit.cs          Arc-length samples, sector-local projection, tangent/lookahead
    CheckpointGate.cs           Ordered directional crossing validation
    RaceProgressTracker.cs     Implements RaceProgressSource; coherent standings per tick
  Runtime/AI/
    AIWaypointDriver.cs         Path following through KartInput, curvature-aware throttle
    KartInputArbiter.cs         One writer: player/AI/autopilot/disabled
    WaypointAutopilot.cs        Implements KartAutopilotPort; hands control back on expiry
  Runtime/Modes/
    GameSession.cs             State machine and lifetime ownership
    RaceRules.cs               Laps, item/AI/hazard policy and result definitions
    GrandPrixSession.cs        Four races, persistent standings and points
    TimeTrialSession.cs        Solo start/finish and best-lap persistence
    BattleSession.cs           Three balloons, elimination, last survivor
    GhostRecorder.cs           Fixed-rate timestamped pose samples
    GhostPlayback.cs           Collision-free interpolated visual replay
  Runtime/Presentation/         Camera, audio, particles, HUD and result views

  Art/Themes/ShatteredCrown/     Stone islands, violet hazards, layered atmospheric backgrounds
```

Input is captured in `Update`, with press/release edges latched until `FixedUpdate`. `KartController` owns physical velocity and orientation. The input adapter never moves a Transform. One input writer is required per kart; the future arbiter switches control during autopilot. Visual spin uses a child, leaving the physics heading intact.

`RaceProgressSource` owns placement and unwrapped track distance. Items and rubber banding only read that contract. They decline to run when no valid snapshot exists. No placeholder waypoint logic silently invents standings. `RaceParticipant.RacerId` must be unique and stable in the session. Future standings must include finished racers in their occupied places and exclude eliminated racers according to mode rules.

`ItemManager` owns the seeded RNG and item creation. An authoritative host owns inventory and damage; the player sends intent. Physics and `System.Random` are not a deterministic lockstep/network protocol. Online replication, validation and reconciliation belong to the later integration layer.

## Core code 1: driving

The complete implementation is in `Runtime/Driving/KartController.cs`, supported by `KartTuning.cs` and the keyboard adapter. No wheel simulation is involved. A dynamic sphere supplies collisions and real mass ratios, while explicit velocity rules supply arcade acceleration, grip and drifting. Upward motion and sideways collision momentum survive driving updates; lateral momentum decays through tunable grip rather than a hard total-speed clamp. Excess forward speed decays toward the current drive target. Reverse is limited to 35% of forward speed.

| Class | Mass | Forward top speed (m/s) | Acceleration (m/s²) | Yaw rate (degrees/s) |
| --- | ---: | ---: | ---: | ---: |
| Light | 90 | 22 | 19 | 135 |
| Medium | 140 | 25 | 15 | 110 |
| Heavy | 220 | 29 | 11 | 88 |

Hold throttle, turn and press Space above 7 m/s. The kart hops, locks a drift direction, and enters a drift on landing if Space remains held. Countersteering adjusts the turn without reversing the locked drift. A signed velocity-to-heading angle between 5° and 75° charges the turbo while grounded. Straight-line holding and falling through the air do not charge it.

| Turbo | Valid drifting time | Forward velocity impulse | Boost duration | Additional speed allowance |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.6 s | 5 m/s | 0.65 s | 7 m/s |
| 2 | 1.4 s | 7 m/s | 0.95 s | 10 m/s |
| 3 | 2.3 s | 9 m/s | 1.25 s | 13 m/s |

Release Space to cash out once. Falling below minimum drift speed or taking a hit cancels the charge. Timers use simulation time, so pause/time scale behaves consistently. Boost impulses are queued for physics, are independent of mass (equivalent to `ForceMode.VelocityChange`), and fit within a boost speed envelope. Simultaneous rewards take the largest impulse and allowance; they do not add indefinitely. A shorter weaker boost never truncates an existing stronger boost.

For jump tricks, leave the track via a ramp or bump, remain airborne for at least 0.24 s, and **press** Space in the last 0.16 s before touchdown. The last airborne press is consumed on landing for +5 m/s and a 0.65 s boost. Holding Space from takeoff does not count. An intentional controller hop cannot farm trick rewards. An airborne trick press cannot accidentally become another hop on the landing tick.

`TryHit` returns whether damage was accepted, cancels boosts/drifting, retains a configurable proportion of planar momentum, and spins the visual child. The default is 1.1 s of spin plus 0.4 s of grace. `Hit`, `TurboLevelChanged`, and `JumpBoosted` are presentation hooks. `IsInvincible` blocks damage. The future battle session subscribes to accepted `Hit` events to pop balloons.

## Core code 2: item economy and rubber banding

Complete source is in `Runtime/Items/` and `Runtime/AI/AIManager.cs`.

| Placement band | Default weighted outcomes |
| --- | --- |
| First/second | Trap 45%, single bolt 35%, coin 20% |
| Middle | Homing bolt 35%, triple bolt 30%, speed boost 35% |
| Last | Invincibility 30%, overdrive 40%, leader hunter 30% |

For eight racers, middle means third through seventh. Larger races extend middle through the penultimate place. In two-racer races, last-place eligibility takes precedence over the second-place defensive band. Solo uses the front band. Integer weights are relative, not required to sum to 100. Negative weights are ignored; an empty/zero table returns a usable coin. Invalid placement is rejected. The default coin caps at 99 and has no hidden speed benefit.

One inventory slot holds any outcome. Touching a box with a full slot does not consume the box. Boxes share a 3 s cooldown per scene instance. E executes the held item. A missing prefab or target does not consume it; firing a targeting item requires a valid target ahead. Triple bolts fire immediately at −12°, 0°, +12° rather than creating an orbiting shield.

| Effect | Execution |
| --- | --- |
| Trap | Stationary, armed after 0.5 s, expires after 25 s, ignores its owner |
| Bolt | Straight swept-sphere projectile, 38 m/s, 9 s lifetime |
| Homing | Steers toward the closest racer ahead in unwrapped progress |
| Short boost | +9 m/s impulse, 1.3 s, +12 m/s allowance |
| Invincibility | Seven seconds, +6 m/s impulse, +8 m/s allowance |
| Overdrive | Five seconds of navigator-owned driving, invincibility, +15 m/s impulse, +18 m/s allowance |
| Leader hunter | Reacquires current first place each physics tick; ignores every other kart |

Projectiles check both initial overlaps and the swept path, ignore their owner, consume themselves on invincible targets, and stop at track collision. The hunter does not attack a former leader after standings change. These are local homing missiles, not route-aware missiles; terrain can stop them. A spline-guided hunter can follow after phase-two navigation exists. Traps stay at their placement pose, so they should be dropped on a grounded track segment; a gravity-settled trap is a future variation.

**Overdrive deliberately requires a concrete `KartAutopilotPort`.** Its complete item-side logic is present; without a navigator it retains the held item and returns false. Before shipping phase one alone, remove its table weight or replace it with a speed boost. Navigation and input handoff will be implemented after review.

Rubber banding uses **unwrapped metres along the course**, never straight-line world distance. With `gap = humanDistance − aiDistance`, the correction is zero within ±15 m and reaches ±1 at 100 m. Default top speed is `base × (1 + correction × 0.06)`; acceleration is `base × (1 + correction × 0.08)`. An AI behind gains at most 6% speed and 8% acceleration; an AI ahead loses the same. Modifiers approach their target gradually, apply to AI only, and return to neutral if disabled, a racer finishes, or progress becomes invalid. No teleporting, player slowdown or inventory manipulation is involved. Split-screen should select a reference human explicitly or later adopt a median-human progress policy.

## Track systems and theme

`SurfaceVolume` composes overlapping restrictions by taking the strongest reduction, and tracks compound colliders so one collider exiting does not clear the entire modifier. Mud defaults to 55% max speed. Any active boost bypasses the restriction; ending it restores mud's cap. Speed adjusts through driving deceleration rather than an instantaneous magnitude clamp. `MovingHazard` moves a kinematic hitbox with `MovePosition` and applies accepted-hit spin/momentum loss; repeated contacts respect hit grace.

`TrackTheme` defaults to **Shattered Crown**: shattered stone floating islands, purple energy hazards, a dark violet sky and layered distant silhouettes. `TrackThemeManager` swaps visual-only environment prefabs and applies fog, skybox and ambient color. Keep actual road colliders, checkpoints, item boxes and hazard logic outside the visual prefab, so theme swaps do not change lap geometry. This is an art configuration and folder contract; art assets are not generated. Fog/skybox settings target the built-in pipeline/URP; HDRP needs a volume-based adapter. Lighting settings are scene-global and should be owned by the active track scene.

Phase-two progression contract:

1. Bake ordered centreline samples with cumulative arc length and ordered checkpoint gates. AI reads lookahead positions and curvature; steering is the signed heading-to-target angle.
2. Validate gate crossings in order, in the forward direction, with crossing hysteresis. Reverse crossings and gate skipping cannot advance a lap.
3. Project the kart only onto its currently validated sector and neighboring legal segments. Avoid global-nearest-waypoint ranking at hairpins, bridges or parallel track sections.
4. Publish `completedLaps × lapLength + sectorDistance` and standings together once per tick, before AI/item consumers. Clamp illegal off-track progress; restore a saved checkpoint and call `ResetTransientState` on respawn.
5. Sort by validated lap/sector/progress; resolve equal progress by stable racer ID, and preserve finish order once a racer finishes. Register the full roster and validate IDs at session start.

These constraints prevent lap-wrap rubber banding bugs and shortcut-induced placement jumps without coupling the controller to a specific track representation.

## Game-mode state machine — design for review

```text
Boot -> ModeSetup -> TrackLoading -> GridReady -> Countdown -> Running
Running -> Paused -> Running
Running -> Results
Results -- GP races 1..3 --> TrackLoading
Results -- GP race 4 / trial / battle --> SessionComplete -> ModeSetup
Any active state -- quit/recoverable load failure --> Cleanup -> ModeSetup
```

`GameSession` will own transitions and cancellation. Scene/track loading completes before grid initialization; countdown enables input only at GO. Only `Running` accepts item actions and records race/ghost time. Cleanup removes active items, cancels autopilot, resets multipliers and disposes mode event subscriptions. Pause freezes simulation time. Finishing must be idempotent so several collisions/checkpoints in one tick cannot award results twice.

| Mode | Setup and completion policy |
| --- | --- |
| Grand Prix | Four track definitions, one persistent roster and standings; freeze each race's finish order; award `[15,12,10,8,6,4,2,1]` for an eight-kart grid (configurable for other sizes); advance only after results; final tie breaks by wins, then latest-race finish order, then stable ID. Define DNF points explicitly (default 0). |
| Time Trials | One human; disable AI navigation and rubber banding, set `ItemsEnabled = false`, clear inventories, remove spawned items, hide/disable boxes and dynamic hazards. Keep static road surfaces consistent. Record a clean lap and compare personal bests. |
| Battle | Enclosed arena with free driving and no lap progression; three balloons each; accepted `Hit` pops one, zero eliminates; last survivor wins, simultaneous final elimination is a draw. Use a separate fixed battle loot policy because race placement has no meaning. The lap-weighted `TryRoll` path remains disabled in this mode. |

The planned ghost format is a versioned record `{trackId, layoutVersion, physicsVersion, sampleInterval, duration, samples[]}` with `{elapsedTime, position, rotation}` at 20 Hz simulation time. Store positions relative to the track root. Replay an independent visual-only object: binary-search adjacent timestamps, lerp position and slerp rotation. Ghosts have no active collider, inventory, hazard interaction or placement entry. Mark teleports/discontinuities to avoid interpolation across respawns; invalidate competitive records on respawn. Impose duration/sample limits, reject incompatible track versions and non-finite samples, and persist only a verified completed lap. Pose ghosts reproduce the route visually; they are not deterministic physics re-simulations. Recorder/playback code remains deferred as requested.

## Scene setup

1. Create a Unity 6 project. Copy this package's `Assets/ArcadeKart` folder into `Assets`. Let Unity generate `.meta` files, then retain them in your actual Unity project. Run **Unlike Hero → Karts → Create Default Assets**. This creates missing assets without overwriting existing tuning.
2. Create layers `Track`, `Kart`, `ProjectileVisual`, `ItemBox`, `Surface`, `Hazard`. Configure collision/query masks intentionally. Use metre-scale tracks, Y-up gravity, a 0.02 s fixed step initially, and uniform positive kart root scale (prefer `(1,1,1)`). Set root sphere radius to approximately 0.5 m.
3. Kart prefab root: dynamic `Rigidbody`, `SphereCollider`, `KartController`, `RaceParticipant`, `ItemInventory`; human karts also get `KeyboardKartInput`. Assign tuning, a **Track-only** ground mask, inventory manager, and unique ID. Assign a separate visual child to `visualRoot`. Keep decorative wheel/body meshes collider-free for this prototype.
4. Give the kart sphere a Physics Material with static/dynamic friction 0, bounce 0, and Minimum combine settings; assign matching road material. Collider friction must not compete with scripted grip. The controller configures gravity, mass, damping, CCD, interpolation and rotation constraints on Awake.
5. Static road mesh/box colliders belong to Track. Create ramp geometry and a broad test landing. Keep trigger volumes out of the ground mask. Handle out-of-bounds through the future TrackManager; currently, a kart falling off an island keeps falling.
6. Session root: `ItemManager`, `AIManager`, `TrackThemeManager`. Assign the same race-progress provider and roster to item/AI managers when phase two is implemented. Until then, use a small debug subclass of `RaceProgressSource` with deliberate Inspector standings to exercise items. No fake standings are active by default.
7. Projectile prefab: `KartProjectile` plus a visual child, no collider/Rigidbody. Collision mask **Track + Kart**. Trap prefab: trigger collider + `DroppedTrap`, with a visual; the dynamic kart Rigidbody supplies trigger events. Keep projectile spawn offsets larger than the kart sphere.
8. Box prefab: trigger collider + `ItemBox`, assign the same manager used by inventories, and a distinct visual child (never assign the box root as its visual). Surface prefab: trigger collider + `SurfaceVolume`. Hazard prefab: kinematic Rigidbody + trigger collider + `MovingHazard`, on Hazard layer. Enable their contacts with Kart in the collision matrix. Size moving triggers adequately for maximum kart/hazard relative speed; trigger sweeps are not continuous collision guarantees.
9. Assign ShatteredCrown to the theme manager and add a visual-only environment prefab/skybox when artwork exists. The scene needs its own light and follow camera.
10. The keyboard adapter supports the new Input System if installed and enabled; otherwise it uses the legacy input manager when enabled. If both are enabled it chooses the new system. Gamepad/touch/remappable actions should call `SetInput` through a dedicated adapter.

## Validation and review boundary

Run **Unlike Hero → Karts → Validate Economy and Rubber Banding** in Unity. It executes weight ordering, placement bands for 1–16 racers, 300,000 seeded loot samples, forbidden-item checks, empty/zero-weight fallbacks, invalid placement handling, and rubber banding dead-zone/saturation checks. This is supplied executable validation, not a claim that Unity was run here.

Before approving handling for production, verify in Play Mode:

- Light accelerates/turns faster; heavy has higher top speed and displaces a light kart more than it is displaced. Test both moving and stationary contacts.
- At 30/60/144 render FPS, a short Space tap always produces one hop. Holding a drift charges each tier and releasing awards once. Air time does not charge it, and damage cancels it.
- A ramp trick press 0.10 s before landing rewards once; 0.25 s early, held from takeoff, and an intentional hop do not. Test trick presses on the exact landing tick.
- Overlapping mud volumes, compound-collider exits and respawns keep the proper restriction. Boosts bypass mud then restore it; repeated boosts remain capped. Reapply a weaker boost after an expired stronger one and verify the old allowance does not survive.
- At a lap boundary, a slightly trailing AI receives a small catch-up adjustment rather than maximum slowdown. A nearby AI across a hairpin uses track progress, not world distance.
- Shoot at a wall, at high speed, and from an initially overlapping spawn. Verify owner exclusion, invincibility, target loss and leader swaps. Confirm a full inventory leaves a box available and duplicate trigger contacts cannot award twice.
- Validate hazard trigger coverage at maximum relative speed, safe respawn poses and input disable during results. These depend on scene geometry and phase-two session ownership.
